# 交接说明：用手机自动抓取高德 2 号线到站时刻表

给本地 Codex / Claude。用户把手机用 USB 连到电脑，由你驱动手机打开高德的到站时刻表页面，把时刻读成文本。不要让用户手动一张张截图。

## 为什么要抓

高德的到站时刻表是上海地铁的官方运行图：已核对虹桥2号航站楼往西首末班 06:05 / 23:58、张江高科往西末班 23:07，都与 `src/data/firstlast.ts` 一致。它只精确到分钟，「开往」只写方向终点，不分交路。所以要抓相邻几个站的全天时刻，比较各站班次数，推出交路、始发站、终到站和运行时段，用来替换 D72 早晚两段的插值假设。已录入的数据见 `reference/timetable-gaode.md`。

## 要抓的站（工作日，两个方向都要）

按优先级：

1. 北新泾
2. 虹桥2号航站楼：往西已录入，只缺往东和 05:00–06:00 段（往西首班 06:05，应当没有）
3. 唐镇
4. 张江高科：往西缺 08:20–22:00，往东全缺
5. 世纪公园
6. 世纪大道（可选）
7. 海天三路（可选）

周末的表等周六、周日再抓同样的站，文件名带 `weekend`。

## 方法

**先确认手机系统**：
- Android（含 EMUI、MagicOS、MIUI 等）用 `adb`。
- 纯血鸿蒙（HarmonyOS NEXT）用 `hdc`，命令对应 `hdc shell uitest dumpLayout`、`hdc shell uitest uiInput swipe`、`hdc shell snapshot_display`。
- iPhone 没有现成的简单办法，告诉用户，退回手动截图。

用户要做的只有：手机打开开发者选项和 USB 调试，连电脑后在手机上点「允许调试」。`adb devices` 能看到设备再往下做。

**优先读界面文字，不要截图再 OCR**：
- `adb shell uiautomator dump /sdcard/ui.xml && adb pull /sdcard/ui.xml`，从 XML 的 `text` 属性里取 `HH:MM到站`，以及小时分组标题 `HH:00-HH:00`、方向标签、`上车站：XXX`。
- 动画没停时 dump 可能报 `could not get idle state`，等一下重试就行。
- 只有 dump 取不到文字（自绘控件）时，才用 `adb exec-out screencap -p` 截图，再用 tesseract `chi_sim` 或其他 OCR 识别。这种情况每条记录要标置信度。

**翻页**：
- 用 `adb shell input swipe` 往上滑，一次滑大约 2/3 屏，保证相邻两屏有重叠行。
- 每屏 dump 一次，按时刻去重合并，连续两屏没有新行就算到底了。
- 折叠着的小时分组（标题右边有 ∨）要先点开。

**导航**：
- 第一个站可以请用户手动打开到时刻表页面。
- 之后在页面里切换「上车站」和方向标签。坐标从 dump 的 `bounds` 里取，不要写死。
- 导航自动化太费劲的话，可以每个站请用户点进去，翻页和读取仍由你自动完成。这已经省掉了用户最烦的部分。

**写进脚本**：放在 `scripts/gaode/`（Python 或 Node 都行，头注释写依赖），可以重跑。

## 输出

- `reference/timetable-gaode/<站名>-<UP|DN>-<weekday|weekend>.txt`：每行一个 `HH:MM`，按时间排序，文件头注释写抓取日期、星期、方向标签原文和行数。
- `reference/timetable-gaode.md` 的汇总表同步更新；已有的手录数据以抓取结果为准，有出入的在报告里列出。

## 校验（写进脚本，抓完自动跑）

- 每个站、每个方向的第一行和最后一行与 `src/data/firstlast.ts` 的首末班一致（±0 min；同一分钟内允许差 1 min）。
- 时刻严格递增，没有重复。
- 每小时班次数打印出来，跟相邻站比，差太多的标出来（可能漏行）。

## 隐私与入库

- **截图不入库**：截图顶部是地图，会暴露用户当时所在位置。临时文件放 `work/`（已 ignore），用完删掉。
- 入库的只有时刻文本、脚本和说明。
- 不要在别的应用里乱点，只操作高德。
