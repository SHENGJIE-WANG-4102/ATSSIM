## 本轮修改

1. **恢复KPI不能靠撤车（D44/D45，修订D27/D37）**
   - 删除“故障全部关闭后”“关闭后45min”这类按KPI窗口计时的撤车/定位。恢复处置只由列车自身状态触发，故障中与故障后一致：备车接替（预计下一始发晚点>300s）、R1（终端预计晚点>600s：定位到可达原图始发，否则清客回段）、R2（错过周期>120s且120–900s内有本车底始发：取消其间往返）、R3（失去车底后由备车顶替）。被接替车底标记 `relieved`，不再适用R1/R2，也不能再被顶替。
   - 中间站规则：本车次晚点>600s时，R4 车次调整（与后方同交路、计划此刻在本站发车的列车互换车次/表号/车底任务，`exchangeDuty` 命令），没有伙伴则 R5（R1提前到中间站：清客定位或回段，被接替列车同样适用）。只靠终端规则，21:00停止故障时在途晚点30min的列车要跑完75min车次才能处理，60min内无法恢复。
   - 新增 `standby.ts`（D45）：三段库存车作备车，出段路径/间隔/通知300s校验，副本上校验运行图通过才生效；学员可用 `standby` 命令手动办理。
   - L1/L2 交付门限 95%/90%（原图载客车次实际完成，不含调整车次）；L3 不再作为soak门限（见已知问题）；一例须恢复KPI与交付同时满足。逐例输出 `within2`、`maxLate`、`cancellations`、`cancelReasons`、`delivery`。
2. **救援受全部安全不变量约束（D46）**：自动RM越过故障信号须道岔位置正确且未在转换（修正一次SWITCH_UNDER_LOAD）；故障车已越过终点站停车标时，连挂后换端到对向站台清客，不再推向身后站台而进入尽头线（修正一次LIVENESS）。重叠检查只豁免 `coupling` 阶段≤1m 的车钩接触；连挂后作为一个编组检查。自动RM（救援接近、越过故障信号）也受已发授权边界检查，只有人工驾驶RM为目视。
3. **救援车RM**：只有缺少MA的原因正是目标故障车（授权终点为其车体，或终点外第一列车即故障车，且其间无其他车体/封锁/敌对条件）才转RM，否则与普通跟随车一样等待。
4. **冒进EB**：只能经冒进处置程序（无线电：核实进路→RM至前方信号机）缓解；调度台 `ebRelease` 拒绝冒进EB，其他原因须 `ebCauseCleared`（通信中断经降级TBTC除外）。
5. **A级完整性报警逐实例**：每个违规实例独立报警键；仅同车、同类、同对象、同内容（数字归一）10s内的重复视为同一事件。
6. **测试完整性**
   - `calibration.test.ts`：核心4–22站两方向、两峰、所有未取消列车（含出入段/定位空车）计划间隔150±5s，高峰带起点第一个间隔即150±5s。
   - 无故障实跑：L0 soak 核对核心站实际发车≥95%间隔在150±30s（≥3000个间隔）。
   - 进博会场景恢复到工作日09:30窗口；删除 addTrain 重试循环。
   - 全日测试 `tests/fullday.test.ts` 删除，改由 `soak:quick` 的L0例覆盖（`npm run simday` 只跑两个base L0例）。
   - 单元测试恢复默认超时 60s：`tests/globalSetup.ts` 先并行生成共享预热检查点（v8序列化，按 src/sim、src/data 哈希缓存在 `node_modules/.cache/atssim-warmup/`），`makeSim(dayType, until, config)` 直接恢复；vitest 改 `forks` 池并行。调度命令测试从 `scenarios.test.ts` 拆到 `dispatcher.test.ts` 平衡各进程。
7. **取消原因**：`cancelTrip` 保留第一个具体原因（撤车含触发规则与预计晚点、救援车、故障车连挂回段、R2、R1定位、人工折返调整、加开能力不足、车底延长运用等）；任一soak例出现无原因取消即失败。
8. **加开（D47，修订D43）**
   - 加开优先延长运用即将回同一车辆段的基本图车底（原回段车次取消并记原因），或接续尚未出段的基本图车底（免出段）；加开车次在端点首尾相接成周转，而不是每趟出段/回段。
   - 仍需出段/回段的加开在排图时避开共用转换轨对向占用；找不到回段时隙可沿行车方向载客续行到前方车辆段回段。日间下达时出段时刻已过的车底不排。
   - 虹桥火车站站前折返在基本图运行时没有空档，加开车延伸到国家会展中心站后折返，仍覆盖虹桥火车站↔广兰路全区段。
   - 基本图本身在±半个加开间隔内没有空档的网格时隙（高峰150s及渐进段）不计入请求，单独报告。
   - 运行中列车在加开生效时改写任务（`extendTrainTasks`）。`DEPOT_CONFLICT` 只把“出段或回段本身是加开动作”算作加开冲突。L0 soak要求实际开行的请求区段加开车次≥90%请求数；交付率分母不含因加开排图取消的原图车次。
9. **西段2'30"/5'00"交替含出入段车（修订D7、D30）**：两端 `MAX_PRESENT` 2→3；外段交替窗口（高峰带两端各收20min）内不安排出入段车，出段车整体前移满足折返。测试检查窗口内外段0–3站所有列车。
10. **低优先级**
    - 客流检查非同义反复：各站登乘份额与权重偏差≤5%，06–23时各小时份额与曲线偏差≤8%；首次运行即发现终点站只得51%权重，已修正 `boardingDemand`（D29补充）。
    - 区间运行晚点按到站计划计算（`etaToStop`，movement.ts）。
    - 运行图校验 `TURN_SHORT` 执行最小折返时间。
    - 豁免原因的计划外停车持续30min报A级运营报警（`EXEMPT_LIMIT`）。
    - 无故障soak例只跑种子1（seed不影响任何门限）。
